## 先给一个贯穿全文的判断

作者把 P1–P5 当成五个独立问题，但我认为**它们有一个共同的错误前提**，这个前提在 P1 和 P4 里表现得最明显：

> 作者假设"可靠地预测/诊断一个奖励函数好不好"是可行的，只是目前的证据通道不够。

我认为在**不训练**的约束下，这个假设本身是错的。原因是一个信息论层面的事实：

**奖励函数是一个函数；策略是那个函数经过优化后的像。** 一个便宜的门控（P4）或证据表（P1）只能观察"函数在若干点上的取值"或"函数各分量的统计量"。而"这个函数优化出来会走到哪里"是**优化过程**的性质，不是函数性质。250 个候选里 3 个被门控接受却 0/60，不是门控"还不够好"，是门控在做一件它做不到的事。

这个判断直接决定了 P4 的答案，也重构了 P1。而 P3 和 P5 的答案要顺着它走：**如果廉价预测不可靠，那么方法的核心价值就必须落在"用训练结果迭代"上——而 P5 要做的，是让迭代的信号存在。**

下面逐题给出答案。

## P1 —— 如何诊断一个"缺失的"激励项

### 直答

**"诊断缺失项"这个提法方向错了，应该问"能否学会识别它"。**

穷举/探测一个以自然语言为输入、结构开放的奖励函数，是一个**定义不良问题**：你无法在任何有限探测集上证明"不存在惩罚 closing speed 的项"，因为下一行代码随时可能引入它。作者现在的 `analyze_terminal_dominance.py` 做的正是这一类事情，它的问题是**它输出一个数，而那个数没有经过任何校准**，所以无法判断阈值在哪。

### 推荐 formulation：偏好排序，而不是分量检查

把"奖励里有没有正确的项"这个**结构性问题**，替换成"**奖励是否实现了正确的排序**"这个**行为性问题**：

设有一组参考行为（reference behaviours），其中每一个都带一个关于任务目标的有序标签。要求是被评估的奖励在这些行为上诱导出正确的偏好顺序。诊断输出不再是"缺少某个分量"，而是"**reward 认为 A 优于 B，但任务要求 B 优于 A**"——这是一条可操作的、可定位的诊断。

这个框架的优势在于它**同时解决了 P1 和 P4**：

- 它不关心奖励的代码结构，所以"缺失项"和"权重错"在它面前**是同一种失败**（都表现为排序错误）。这正好绕开了作者"缺失项不可观测"的困境——**你不需要观测缺失项，你只需要观测排序错了。**
- 它是一个**有判别力**的检查（关于判别力的讨论见 P4），因为它约束的是输入输出关系而非代码形式。

#### 参考行为集合怎么构造（这是关键，也是唯一的技术难点）

不能用"手工设计的合成状态"，理由见 P4。必须用**轨迹**，而且必须覆盖"任务上等价但奖励上不该等价"的对照：

针对本环境，参考集应该包含这些成对行为：

| 对 | 行为 A | 行为 B | 任务要求 |
|---|---|---|---|
| 1 | 以 0.2 m/s 进入 dock 并停住 | 以 1.5 m/s 冲进 dock 并停住 | A ≻ B |
| 2 | 在 dock 外 0.1 m 处悬停 | 正确 dock | dock ≻ 悬停 |
| 3 | 低 closing speed 释放、靠 drag 滑入 | 全程高速推入 | A ≻ B |
| 4 | 撞 3 次以上硬冲击完成 dock | 无硬冲击完成 dock | A ≻ B |

**关键点：这些对是"任务上等价或近乎等价、但正确奖励必须区分"的对照。** 一个把"docked vs not docked"当唯一信号的奖励，会在对 1、3、4 上给出**平局或错误排序**——而**平局本身就是诊断信号**。这比"检查有没有某个项"强得多，因为"平局"是函数求值的结果，不需要假设解的结构。

### 文献锚定（置信度见文末）

这个概念在文献里有多个成熟入口，作者需要的是正确检索词：

1. **Reward hacking / specification gaming 的检测**：最接近的框架是"奖励在分布外或对抗性构造的输入上失效"。入口词：*specification gaming*、*reward hacking*、*adversarial reward evaluation*。代表工作：Amodei et al., 2016, *Concrete Problems in AI Safety*（其中 concrete problem #5 就是 reward hacking）——这条我置信度很高。
2. **偏好排序框架本身**：如果参考行为带偏好标签，那么"奖励实现了正确排序"正是 **preference learning / reward model evaluation** 的标准评估口径（pairwise accuracy、ranking accuracy）。入口：Christiano et al., 2017, *Deep RL from Human Preferences*（置信度高）；以及 reward model 评估里对成对排序准确率的使用。
3. **反事实/可辨识性视角**：作者问"有没有更好的 established formulation"，我认为最贴切的是**奖励可辨识性（reward identifiability）**：给定行为数据，哪些奖励函数在行为上不可区分（Ng & Russell, 2000, *Algorithms for Inverse Reinforcement Learning* 关于"奖励与最优策略之间的不可辨识性"）——置信度中高。这给了"为什么不能凭结构判断好坏"的理论依据。
4. **"分量表看不见缺失项"这个困境的正式名字**：这是**欠定规格（underspecification）**问题，而非观测问题。我没有找到把"奖励欠定"和"分量激活统计"直接联系起来的专门工作，这一点我认为**没有已发表对应物**，是作者问题的一个真实新点。

### 可证伪预测

- **预测 1**：如果偏好排序诊断有效，那么在 `analyze_terminal_dominance.py` 现有的 24 个候选上，用排序一致性打分，应该能把 pilot 4 个候选和 old-spec 20 个候选**完全分开**（文件 3d 已给出：terminal-credit ratio 1.02–1.24 对 172–5123，本来就能分开，所以这一步只是复现）。
- **预测 2（真正的检验）**：在 v4 那 16 个"四项全过"的候选上，排序一致性**应该显示出方差**。如果它和 3e 的 gentleness 检查一样**恒等于 1**，那么这个诊断也没有判别力，我的推荐就是错的。

### 失败条件

如果排序诊断在 v4 的 16 个候选上**全部通过**，而那 16 个里至少有 3 个（实际训练过的那 3 个）是 0/60，那么排序诊断和作者现有门控**犯同样的错**——因为"通过排序检查"仍然不能预测训练结果。这直接把我推向 P4 的结论：**廉价静态诊断原则上不可靠**。

### 工作量

参考轨迹可以用**脚本化控制器**生成，不需要训练。4 对行为 × 每对若干条轨迹，成本是几十次仿真，秒级。真正的成本在于**设计参考行为对**——这是人的工作，不是代码的工作。这是我认为作者最该投入的地方。

### EUREKA 信息不对称（作者要求的第三点）

排序诊断**对两边都可用**，所以它本身**不产生 C**。这是一个必须正视的事实：P1 的答案**不能**解决 P3 的 C 条件。作者要求"解释为什么它对 CREATE 有信息而对 EUREKA 没有"——我的答案是：**它没有，而且不应该有**。理由见 P3：任何只看奖励文件的诊断，两个方法都能做。C 必须来自**方法流程的结构差异**，不能来自诊断工具。把这句话说白一点：**P1 的答案改进的是搜索质量，不是方法对比的可区分性。**

## P2 —— 接口规格 vs 泄露答案的界线

### 直答

**判据是：该条款是否把"环境/评测施加的约束"与"方法应当自行设计的自由度"混在一起。**

具体地，我给一个可执行的判定流程，三条问题，任一为"是"即判为泄露：

**判定流程（对每一条 prompt 条款依次询问）：**

1. **必要性**：禁止该条款后，产出的候选是否**全部不可行**（而非仅仅不好）？如果只是"质量下降"，它是泄露。
2. **自由度**：该条款是否消除了解空间中的一个自由度？如果禁用后候选实现开始发散，而启用后**全部收敛到同一种实现**，它是泄露。
3. **分布检验（最关键，且可实测）**：在两个方法各自的候选集合上，该条款是否导致**跨候选方差显著下降**？如果启用后所有候选都抄同一段代码，它是泄露。

第 3 条是唯一有操作性的检验，因为它**可以测量**：给定 N 个候选，比较启用/禁用该条款下方差的差异。文件 3e 已经无意中给出了这个检验的完美实例——gentleness 检查 16/16 通过，因为所有候选抄了同一段代码。**方差为零 = 该条款泄露了实现。**

### 用它判定作者要的五条

| 条款 | 判定 | 理由 |
|---|---|---|
| 每步奖励裁剪到 ±20 | **(a) 接口** | 这是 harness 施加的约束（文件第 2 节明确：`RewardOverrideWrapper` 默认 clip 20）。不写它，候选会在错误的尺度假设下工作。禁用后不是"发散"，而是"普遍不可行"。 |
| 成功时回合终止 | **(a) 接口** | 环境语义，文件第 1 节明确。这是任务规格的一部分，不是设计选择。 |
| 奖励必须在脚本化状态上让 docked 优于 parked | **(b) 泄露（边界情况，应移出门控）** | 这条**很难判**，我倾向于判泄露，理由值得展开：它没有给出实现细节，但它**直接给出了设计目标**——而"用一个一次性终端事件让 docked 压倒 parked"正是文件 3d 指出的那个 ~1000 倍设计变化。把它写进 prompt 等于告诉方法"你要解决的问题是什么"。**但它作为检查项（而非 prompt 条款）是合理的**——这正是我在 P1 推荐的排序诊断。所以正确的处理是：**移出共享 prompt，放进评测门控。** |
| 用一个一次性终端事件表示完成 | **(b) 泄露** | 这是实现形式。文件 3e 显示正是这一项的引入让 v3b 从 6/16 跳到 16/16——即它把方法差异抹掉了。这是最明确的泄露。 |
| gentleness 项形式为 −0.05 · contact · max(0, v_cart − v_crate) | **(b) 泄露，最严重** | 给出了特征、符号、权重。作者自己已经识别出来（P2 原文说"giving the gentleness formula"）。 |

### 分层方案

```
Layer 0  任务规格层（两方法共享）
         - 环境动力学、观测/动作空间、终止与成功条件
         - harness 事实：clip 值、奖励是逐分量可加的
         - 可用的 info 字段有哪些、哪些没有（"没有 impulse 通道"属于此层）
         → 判据：这些是"你不能改变的"

Layer 1  评测口径层（两方法共享，但以"要求"形式给出）
         - 成功判据（fresh-seed 成功率、阈值）
         - 参考行为的偏好约束（P1 的排序要求）
         → 关键：以"必须满足的性质"给出，不以"如何实现"给出
         → 这一层是 P2 争议的核心，我主张放这一层而非 Layer 0

Layer 2  方法专属层（不共享）
         - CREATE：结构化证据的形式、诊断-编辑流程
         - EUREKA：种群、反思形式
         → 这里才是方法差异的载体
```

核心主张：**作者犯的错不是"给了骨架"，而是"把 Layer 1 的内容（该满足什么性质）以 Layer 2 的形式（该实现成什么样）写进了 Layer 0（共享层）。"** 一旦 Layer 1 和 Layer 2 混了，方法对比就失去意义。

### 文献锚定

这个现象在文献里的正确检索词（我认为这几条置信度中高）：

- **Scaffold / prompt 泄露导致的评测污染**：入口词 *evaluation contamination*、*prompt leakage*、*data contamination in LLM evaluation*。最接近的正式表述在 LLM 评测的方法论批评里。
- **能力归属问题（attribution）**：当性能提升来自 scaffold 而非被比较的组件时，称为 *scaffold confounding* 或 *attribution problem*。这是 agent 评测文献里的活跃议题。
- **Ablation 设计中的"共同提示词"问题**：在**因果推断**里这个结构有标准名字——两臂共享了一个**中介变量（mediator）**，于是处理效应被吸收，这叫做 **over-control / bad control**（Angrist & Pischke, *Mostly Harmless Econometrics* 里的 bad control 问题）。**我认为这是最贴切的正式框架**：把解法写进共享 prompt，等于在比较两个方法时控制掉了它们本该产生差异的那个变量。置信度中高，且这个类比我认为作者会喜欢，因为它把问题从"提示词工程"提升到了"实验设计"。

### 可证伪预测

- 按 Layer 0/1/2 重新分层后，在 v4 那 16 个"四项全过"的候选上重做 generation-only A/B：**跨候选方差应该显著上升**（不再 16/16 全过同一项）。
- 更强的预测：分层后，CREATE 和 EUREKA 的候选分布应该出现可测量的差异。

### 失败条件

如果重新分层后，跨候选方差**仍然很低**、且两方法候选仍然高度相似，那么"泄露"不是方法对比失效的原因，我的分层方案无效。此时真正的原因可能在**基础模型太强/太同质**，即两方法都被同一个先验主导，这需要换基础模型或换更难的规格来验证。

## P3 —— `FragileCargoDock-v0` 是否结构上无法体现方法优势

### 直答

**作者对 A/B/C 的自评基本正确，但他选错了 C 的替代方案，而正确的路径不是"制造 C"，是承认这个环境不测 C、改测别的东西。**

### 先评判他的预测变量

作者提的候选是"**初始奖励分布落在阈值附近的质量**"。我认为它**不是**正确的性质，理由具体：

这个量衡量的是"**离成功有多近**"，但它混淆了两件不同的事：

1. **分量缺失**（结构问题）
2. **分量权重错**（参数问题）

LunarLander 的初始分 −70.4…+139.5（阈值 200，最优 70%）和 FragileCargoDock 的 ≈2% 在这两件事上**无法区分**。按文件 3b 的实测，FragileCargoDock 的失败是**一个缺失项**（probe D 加一项就从 0% → 73.3%），而 LunarLander 论文案例是**权重错**（"把三个稳定系数乘以 5"）。这两个环境的"初始分接近阈值"程度确实不同，但**决定方法能否体现优势的不是接近程度，是失败模式的结构**。

### 推荐的性质：结构可修复性判据（我给出的定义）

我给一个我认为更正确的、且**部分 a priori 可测**的性质。定义两个量（两者都只需在**朴素奖励**上做探针，不需训练）：

**R1 —— 单点修复敏感性（single-edit sensitivity）**
在朴素奖励上施加一个**单分量编辑**，使一个**现成的脚本化控制器**的排序/回报发生显著跃迁的最大幅度。

本环境实测支撑：control v1 → probe D，**一个分量**，0% → 73.3%。这个量很大。
LunarLander：改三个系数（也是小编辑），3/5 → 5/5。也大。

所以 R1 **不能**区分两者。这说明"可修复性"不是关键变量。

**R2 —— 修复的语义可定位性（locatability）**
这是我认为真正的判据：

> 修复必须作用于**朴素奖励中已经存在的分量**，还是**引入一个不存在的分量**？

- 若存在 → 证据表（activation rate / magnitude share）**能**暴露它 → **C 成立** → 诊断引导搜索有优势。
- 若不存在 → 证据表**看不见** → **C 不成立**。

而 R2 **是 a priori 可测的**，测法就是文件 3b 已经在做的实验：**对朴素奖励做单变量增删，看是"调权"有效还是"加项"有效。** 更省成本的形式：枚举朴素奖励的每个分量，逐个做"置零/放大 k 倍"的扰动，测量脚本化控制器回报的响应谱。

**具体判据（我建议的版本）：**

> 设朴素奖励有分量 $c_1..c_n$。令 $S_k$ 为"只把 $c_k$ 的权重放大/缩小一个数量级"所导致的脚本化控制器回报变化。
> - 若存在某个 $k$ 使变化显著（相对其他分量），且最大变化来自**已存在的分量** → **C 成立**（缺陷是尺度问题）。
> - 若所有 $S_k$ 都接近 0，只有**新增分量**才产生变化 → **C 不成立**（缺陷是缺失问题）。

这个判据的价值：它直接对应"证据表能否看见缺陷"，因此**有机制上的理由**预测方法差异，而不是仅靠相关。而且它便宜——纯仿真，无训练。

### 对 C 的正式刻画（我建议作者写进论文的定义）

C 成立当且仅当：**存在一个编辑算子类 $\mathcal{E}$（L1/L2 级小编辑），使得对朴素奖励 $r_0$，$\max_{e \in \mathcal{E}} \text{Perf}(e(r_0))$ 显著高于 $\text{Perf}(r_0)$，且该最优编辑所修改的分量在 $r_0$ 中的 activation rate / magnitude share 统计量上**可被检出异常**。**

第二句是 C 的本质。第一句是 A（可修复性）。**A 与 C 的区别就在第二句**——这正好对应作者的判断"A 成立、C 不成立"：本环境里那个有效编辑是**新增**一个分量，它在 $r_0$ 的统计量上**不存在**，所以无可检出异常。

我认为这是对作者问题的最直接回答，而且它把 A 和 C 从"两个模糊条件"变成了同一条式子的两个部分。

### 构造提供 C 的环境（原则性方法）

作者顾虑"自建环境会被质疑为方法定制"。我给的构造原则是：

**不要让环境去"提供 C"，让环境去"提供天然的竞争目标（competing objectives）"。**

具体地：设计任务时，确保**每个朴素奖励设计都会自然地包含至少两个目标，而这两个目标在最优策略上冲突**。这样：
- 朴素奖励必然包含需要调权的分量（因为目标明显到不得不写进去）→ C 成立
- 而环境本身是"有内在张力"的，不是为了某个方法设计的 → 效度威胁大幅缓解

本环境的问题恰恰是：**"不要撞得太狠"这个目标在朴素设计里不自然会写进去**（作者的控制 v1 就没写）。所以 C 不成立。改造方向见 P5。

关于效度威胁，我的判断是**不可消除，只能缓解**。可行的缓解手段：

1. **报告一个环境族，而不是一个环境**：3–5 个任务，报告判据（上述 R2/响应谱）的取值与实测优势的相关性。这样论点从"我在这个环境上有效"变成"优势随判据值单调变化"——**后者不受"你为方法设计环境"的质疑**，因为你预测的是一条趋势，不是单点。
2. **事前注册判据**：在跑方法之前，先计算 R2 并公开预测"这个环境上 CREATE 应该赢/不该赢"，然后跑。这是最有力的做法。

### 可证伪预测

- 在三个环境上计算响应谱判据，预测与实测优势（CREATE − EUREKA）应**同向**。
- 在本环境上，判据应预测"无优势"——这与作者实测（3c：无差异）一致。**这一点已经被现成数据部分证实了**，这是个好迹象。

### 失败条件

如果在 BipedalWalker 或某个新环境上，判据预测有优势但实测无优势（或反之），判据被证伪。特别地：**如果 LunarLander 和本环境的响应谱判据值相同但实测优势不同，我的判据就是错的**——因为这两个环境是作者手上唯一有方法对比数据的两个。

## P4 —— 廉价结构门控能否救回来

### 直答

**不能作为"预测器"，但能作为"过滤器"。作者应该放弃把它当选择器的野心。**

### 为什么不能（机制性论证）

门控在**合成状态**上探测奖励。它接受 3 个 0/60 的候选，这个失败不是调参问题，是**范畴错误**：

- 门控能验证的是：奖励函数在**指定的点**上满足指定性质。
- 训练结果取决于：奖励函数在**策略访问到的整个状态分布**上的形状，以及优化过程。

关键在**策略会移动状态分布**。一个在 dock 附近满足"docked ≻ parked"的奖励，完全可以在策略实际访问的分布上（高速接近区、边界区）给出病态的梯度。文件 3c 的证据完全支持这一点：**同一个奖励在 1.2M 时 8.3%、在 3M 时 0%**——奖励函数**没变**，只有策略变了。**一个纯函数性质的门控，原理上无法预测一个随策略变化的结果。** 这是我认为最有力的"原则上不可学"论证。

### 作者两个方向的评估

| 方向 | 我的评估 |
|---|---|
| **探测脚本化控制器回报** | **这是正确的方向，但它已经不是"门控"了。** 一旦你要求门控评估控制器回报，你就必须定义"好回报是多少"——而这就是在训练一个策略无关的价值基准，本质上等价于一个**离线评估器**。它有用，但成本从"秒"涨到"分钟级"，而作者选门控的动机（省 25 分钟）被削弱。 |
| **要求奖励正确排序参考轨迹库** | **这是最好的方向**，理由见 P1：它把结构性检查换成行为性检查，而且**天然有判别力**（见下）。但它同样不能预测训练结果，只能保证"语义正确"。 |

**我的建议：两者都做，但改变它的定位**——不是"选择器"，而是"**可行性过滤器 + 诊断报告**"。用它把明显破损的候选（越界、无边界 guard、平局）剔掉，减少无谓的 25 分钟训练，**但不要用它的分数排序**。选择仍然要靠训练，但可以用**更省训练的早期信号**：例如 1.2M 步的 fresh-seed 成功率（文件 3c 显示这已经足够便宜且信息量高于 `mean_eval_reward`）。

### 判别力的一般构造法（这是作者最需要的部分）

从 3e 的教训出发：gentleness 检查 16/16 通过是因为**所有候选抄了同一段代码**，方差为零。**方差为零的检查，判别力恒等于零，无论它多"正确"。**

所以有判别力的检查必须满足两个条件：

1. **候选间有方差**（否则信息量为 0）
2. **该方差与训练结果相关**（否则是噪声）

构造方法：

- **步骤 1**：找出朴素设计与错误设计的分歧点，而不是正确设计与破损设计的分歧点。即：**检查项必须能区分"看起来都合理"的候选**。gentleness 检查之所以失败，是因为它检查的是一个所有候选都从 prompt 抄来的常数。
- **步骤 2**：**在跑门控之前，先测量候选间的方差**。若某项方差 ≈ 0，直接删掉该项，不管它多合理。这是一个纯操作的规则，成本为零。
- **步骤 3**：**用留出的训练结果校准阈值**。作者没做的正是这件事：他有一个门控，有 5 个候选的训练结果（2 个被拒 0/60，3 个被收 0/60），**但没有用这 5 个点去拟合/校准门控的判据**。他知道门控没有预测力，但没做的是：**问"哪个单项有预测力"**。有了 3e 的 16 个候选 + 至少几个的训练结果，就可以做单变量分析。

**这是我认为作者最该做的一件具体事**：把 3e 的 16 个候选按四个检查项**逐项**统计与训练结果（哪怕是 1.2M 的）的相关性，而不是看"四项全过"这个合取。合取是最没有判别力的形式，因为它把方差都吃掉了。

### 可证伪预测

- 逐项分析后，应该发现**至少有一项**（我猜是"hover cannot out-pay docking"的 episode-credit ratio）与 1.2M 成功率有可测相关，而"gentleness"项相关性为零。
- 如果**四项全都零相关**，那么廉价门控**彻底不可救**，我的"逐项分析"建议也被证伪。

### 失败条件

如果逐项分析与训练结果全部零相关，那么任何基于合成状态的检查都没用，作者的动机（省训练）只能通过"更短的训练 + 更多种子"来实现，而不是通过探针。这会是我这套建议的失败。

### 替代 `mean_eval_reward` 的选择方案

作者指出 20 个固定种子的 `mean_eval_reward` 几乎无信息（+17.694 → +7.716，且选择种子与评估种子重叠）。我的替代建议：

1. **换指标**：用 **fresh-seed 成功率**（binary）而非平均回报。文件 3c/3e 显示，在 0–5% 成功率区间，平均回报是一个被少数高回报异常回合主导的量，而成功率更稳健。而且它是**最终指标**，避免了"选择指标与报告指标不一致"的问题。
2. **换选择种子**：选择用的种子必须与评估用的种子**不相交**。作者已经发现训练种子就是选择种子（P4 原文），这是 selection bias，必须切断。
3. **换预算分配**：与其花 25 分钟训练少数候选，不如花更少步数训练更多候选、用更多种子评估。1.2M × 更多候选 × 更多评估种子，在 0–5% 区间比 3M × 少候选更有效率——文件 3c 已经显示同一奖励在 1.2M 时 8.3%、3M 时 0%，说明 3M 并没有带来更好信号，反而带来"回报单调上升但成功率归零"的假信号。

## P5 —— 制造条件 C 的最小环境改动

### 直答

**不做"最小改动"，做"最小改动 + 一个可测的判据"，并且这个改动我已经能具体给出——但它是否真的产生 C，必须用 P3 的响应谱判据验证，不能靠论证。**

### 先排除作者的顾虑

作者已经正确证伪了"加时间压力"（两个方法的证据通道都有 episode length 和 termination breakdown）。这个排除是对的。

我也要排除一个更诱人的错误选项：**不要靠"加噪声/加难度"来制造 C**。理由同 P4：难度提高只降低成功率，让选择更不稳，不会改变失败模式的**结构**。

### 我建议的具体改动

**核心思路：让"不要撞得太狠"这个目标在朴素奖励中变得"明显到不得不写进去"，但给它一个错误的权重。**

具体地，在**任务规格（Layer 0）**中加入一个可见的、必须被优化的机制：**crate 的损伤状态（damage）**。

- 环境已经有 hard impact 计数（≥3 次 peak normal impulse > 5 N·s 则失败）。改动是：**把"损伤"从二值失败条件改为一个连续的、可观测的累积量**（例如累积冲击冲量 `cumulative_impulse`），并在 **观测中暴露**它（`obs` 从 19 维扩到 20 维）。
- 同时，**成功条件不变**（仍然要求速度 < 0.05、10 步稳定）。

为什么这个改动能制造 C：

1. **连续损伤量是可观测的、显式列在观测里的** → 任何朴素奖励设计都会自然地写一个惩罚项（因为观测里有它，不写显得不合理）。→ 分量**已存在**。
2. 但它的**权重**会是错的，因为朴素设计不知道"损伤预算"与"精度要求"的兑换率。权重太小 → 策略仍然高速冲入（现在的失败模式）；权重太大 → 策略变得过度保守、不敢接近 dock（新的失败模式，**而且这个失败模式在证据表上表现为该分量的 magnitude share 异常高**）。
3. **关键：这个改动把失败模式从"缺失项"变成"权重错"，而且证据表能看见它**——因为该分量存在于奖励里，所以它的 activation rate 和 magnitude share 会被计算出来。权重过大时 magnitude share 会显著异常。**这就是 C。**

### 论证它真的产生 C（作者要求的关键挑战）

我在 P3 里给的判据正好可以用于检验。作者应该这样验证：

1. 用 P3 的**响应谱实验**：在朴素奖励上，只调 `cumulative_impulse` 惩罚项的权重，扫描一个数量级。测量脚本化控制器回报的变化幅度 $S_{\text{impulse}}$。
2. **C 成立的判据**：$S_{\text{impulse}}$ **显著大于 0**（即调权有效），而**所有其他分量的 $S_k \approx 0$**。
3. **区分"C 成立"与"两边都变好"**：这是作者最尖锐的追问，我的回答是——

> 用**证据表的可分性**来区分。C 的操作定义是"缺陷在 CREATE 的证据中可见、在 EUREKA 的分数中不可见"。所以检验方法是：
> - 计算"最优权重的候选"与"朴素权重候选"在**证据表上的距离**（用 activation rate / magnitude share 向量）。
> - 如果这个距离**大**，而两者的 `mean_eval_reward` 距离**小**（因为回报曲线可能相似甚至反向），那么 C 成立：**证据能分开它们，分数不能。**
> - 如果两者都大或都小，C 不成立，改动失败。

**这个检验是可执行的、便宜的（仿真级或最多 1.2M 级），而且直接对应 C 的定义。** 这是我给作者的最具体的东西。

### 是否破坏 A 或 B

- **A（可修复性）**：这个改动**增强** A。因为修复就是调一个已存在分量的权重，是一个 L1 级编辑（作者自己的分类：L1 parameter tuning）。这正是 CREATE 设计来做的操作。
- **B（保留性）**：这个改动**增强** B。朴素奖励里包含多个正确分量（progress、approach、boundary guard、terminal），而"未约束重写"很容易在调整损伤权重时把 terminal 规则或边界 guard 丢掉。这给了 B 一个自然的载体。

所以三条件同时满足——**这是我认为本改动最大的优点**：它在 A、B、C 上都是正向的，而且不需要动核心力学（不改变"必须提前释放"这个任务本质）。

### 如果最小改动不存在

我认为**存在**（上面的方案），所以不走这条分支。但我要诚实说明一个**备选且我认为同样合理的路径**，因为作者提到了：

**接受这个环境测的是另一种能力，转而扩展证据通道。** 具体要扩展的字段（作者要求具体字段，不要空话）：

```
trajectory_probes:
  - release_speed_at_first_contact: 首次接触 dock 区域时的 crate 速度
  - closing_speed_at_contact: max(0, v_cart - v_crate) 的分布（p50/p90/max）
  - dock_entry_dwell_breakdown: 在 dock 内的步数 vs 满足速度阈值的步数
  - settling_margin: 达到成功条件时的速度余量 (0.05 - v) 分布
  - impulse_histogram: 冲击冲量的直方图，而非仅计数
  - boundary_clearance_min: 轨迹到边界的最小距离
```

**为什么这些对 CREATE 有信息、对 EUREKA 没有？** 我要给出诚实的答案：**它们对两者都可用，所以不产生 C。** 但它们对 CREATE 有信息的地方在于：CREATE 的证据是**结构化、按分量组织**的，轨迹探针可以挂在分量上（"哪个分量在这条轨迹上激活了"），而 EUREKA 的反思输入是**聚合分数 + 反思文本**，轨迹探针在它的接口上没有挂载点。

**但这个论证很弱，我必须承认。** 如果 EUREKA 的反思也接仿真探针，它同样能用。所以这条路径**不解决 C**，只解决"诊断质量"。这印证了我 P1 的结论：**诊断工具的改进不产生 C。C 只能来自失败模式的结构（P5 的改动）。**

## 对抗性追问：我认为作者最可能错的论断

我挑 P3 里一个，因为它决定了整篇论文的框架。

### 论断

> "**A 和 B 大概成立，C 不成立。**"（P3 原文）

### 为什么我认为它可能错

作者把三个条件当成**环境属性**，但我认为 **C 不是环境属性，而是环境 + 方法流程的联合属性。**

理由：C 的定义是"缺陷在 CREATE 的证据中可见、在 EUREKA 的分数+均值中不可见"。这个"可见性"取决于**证据通道的结构**，而证据通道是**方法的一部分**，不是环境的。同一个环境，如果给 EUREKA 也接上 per-component activation 表，C 立刻消失。

- 若 C 是环境属性 → 论文主张"我们找到了一个显示方法优势的环境类别"
- 若 C 是联合属性 → 论文只能主张"在证据通道不对等时，结构化证据有优势"

**后者其实是一个更强、更诚实、也更难被反驳的主张**，而且它解释了作者在 LunarLander 上看到的优势（那里 C 成立，因为 EUREKA 的证据确实没有分量表）。我建议作者**改用后一种表述**，这甚至可能让 P3/P5 的困境变得不那么致命：论文不必找到"有 C 的环境"，只需展示"优势随证据通道的不对等程度变化"。

### 证明我错的条件

如果 EUREKA 的反思输入**实际上已经包含** per-component 的 activation / magnitude share（我在文件里看到 `run_eureka_population.py:175-230` 是"同类东西"，但没读到具体字段），那么 C 就不是联合属性而是环境属性，我的批评不成立。**这是可以立刻查证的一件事——作者只需要打开那个文件看字段列表。** 这也是我认为他该先做的一件事，成本几分钟。

## 修正记录（经对抗性审稿后）

以下是我在收到一次敌意审稿（专门攻击本回答的 10 条论证）后的实质性修正。**我保留了原始论证以便对照，但以下条目推翻或大幅修改了它们。**

### 修正 1（推翻）：ARG-3 的符号反了 —— P3 的响应谱判据

**原主张**：某个已存在分量的 S_k 大 ⇒ 缺陷是尺度问题 ⇒ C 成立 ⇒ CREATE 有利。

**为什么错**：S_k 大意味着**单一主导标量**控制性能，而这**恰恰是 EUREKA 种群 + 数值变异最容易撞对的区域**——盲目重采样一个权重，高概率落在好值附近。我的判据只证明了"存在参数修复"（关于**可达集**的事实），**完全没有证明"CREATE 赢"**（方法优势需要修复**可从证据辨识、但盲搜不可达**，两者是不同命题）。我把它们混为一谈。

**两个真实的混淆**（任一都使实验返回假的"缺失"）：

1. 文件记载 `normalize_reward=true`。权重放大 10 倍 → running std 同步放大 → 归一化后 r 几乎不变 → **S_k ≈ 0**，于是纯尺度缺陷被误判为缺失缺陷。
2. **±20 裁剪**：文件 3d 记载老规格的 dock 奖励**恰好钉在 20.00**。加大其权重，回报变化**为零**。

**修正后的测量方式**：不用回报变化，改用**动作排序变化**——在固定状态集上，扰动某分量权重后 argmax 动作是否改变。此量对正仿射变换不变，**天然免疫归一化与裁剪**。并且必须显式断言裁剪未激活、归一化已关闭。

### 修正 2（推翻）："零方差就删检查项"是错的

**原主张**：某项在候选间方差 ≈ 0 ⇒ 判别力为零 ⇒ 删掉。

**为什么错**：方差是在**已通过检查**的候选上测的。16/16 全过是**由构造决定的**，不能说明该检查无因果价值。此规则会**恰好删掉正在做过滤工作的检查项**——它们零假阴性、多假阳性，"必要但不充分"，边际方差为零却不可或缺。且该主张与"标签不稳"自相矛盾：与零方差结果求相关是未定义的。

**修正**：改用 **leave-one-check-out**——从 prompt 移除检查项 k，重新生成 20 个候选，训练 top-3，测量失败率变化。这测**因果贡献**，而非幸存者之间的相关性。

### 修正 3（大幅降级）：门控"原则上不可能预测"

**原主张**：门控只能观察函数在指定点的取值，无法预测随策略变化的结果，故原则上不可能。

**为什么过强**：
1. n=5 个候选（2 拒坏的、3 收坏的）**远不足以建立零预测力**。旗舰证据也有统计问题：1.2M 的 8.3% 是 1/12 还是 5/60？若 1/12，p≈0.33，纯噪声；即使 5/60 对 0/60，Fisher 双侧 p≈0.057，且 60 种子/臂**无法区分 0% 与 8%**，需约 150 种子/臂才有 80% 功效。
2. 一个在**该奖励自身诱导的策略的 rollout 上**评估 r 的门控，仍然满足"函数在选定点上的性质"，却可以做预测。所以"不可能"是错的。

**正确的表述**：**廉价与可预测二者不可兼得。** 要做到可预测，门控必须在该奖励下做策略优化或离策略评估（importance weighting / DAgger 式修正），成本从秒级升到分钟-小时级，**失去其相对于训练的全部意义**。结论不变，理由必须改。

**另外**：+17.694 → +7.716 的正确机制是 **winner's curse**（16 候选取最大的期望 ≈ 1.77σ，观测差 9.98 ⇒ σ≈5.6），是**确定性**效应，用不相交种子即可消除。我原来的药方对，归因错——不是标签不稳。

### 修正 4（推翻）：P5 提议的改动要制造的条件已经存在

**原主张**：把损伤改为 obs 中可见的连续量，可让分量"存在但权重错"，从而产生 C。

**为什么错**（用我引用的数据反驳我）：
1. 因果前提"可见 ⇒ 会写"被反驳：老规格 **20/20 候选都没写足够的 closing-speed 项**，尽管 closing speed 完全可从 19 维 obs 算出。**可见性 ≠ 会写。**
2. **该条件已实现**：v4 的检查项含"写 closing-speed 项"，16/16 通过，训练三个全 0/60。**我在提议重建一个已实现且已无优势的条件。**
3. obs 19→20 使**所有现有数字失效**（0/60、73.3%、40%、98.3%）。
4. 失败空间**过定**：有候选因缺边界守卫 40/40 越界（另一个独立缺失分量），故"单一 C 解释 0/60"不成立。

**修正**：降级为**待验证假设**，用 2×2 factorial 检验（Factor A: obs 19 vs 20；Factor B: v3 vs v4 prompt），主测指标 M1 = 候选中引用损伤信号的**比例**。**可证伪点：20 维下仍 ≤50% ⇒ 核心机制死亡。**

### 修正 5（推翻）：ARG-8 的距离比较不可证伪

**原主张**：比较"最优权重候选"与"朴素权重候选"在证据空间与分数空间的距离，前者大后者小则 C 成立。

**为什么错**：单对比较、两种任意单位、无零分布、无阈值，且**预设已知最优权重**（事后性）。与修正 3 冲突：若改用成功率选择，分数空间分离重现，C 消失。更根本地：若证据距离在许多**结果相同**的候选对上都大，则该向量**非单射**，不能作为判据。

**修正后的检验**：对大量 (候选, L1 修复后) 对，计算 Δscore 与 Δevidence。**C 成立当且仅当 sign(Δevidence) 预测 sign(Δscore) 的 AUC ≫ 0.5，且在打乱/无关扰动控制下 AUC ≈ 0.5**，使用配对同评估种子，n ≥ 200，并对证据向量做置换零分布。低于此标准即为曲线拟合。

### 修正 6（修正）：C 应形式化为四元谓词

原回答在"P3 对抗性追问"里主张 C 是环境与通道的**联合**属性。审稿人给出了更精确的形式化：

> **C(E, O, X, B)**：环境 E、证据/观测通道 O、编辑算子类 X、预算 B。
> 分解为四个合取项：
> 1. 存在 e* 使 ΔPerf 大 —— **环境性**
> 2. e* 在**基线**算子类内、预算内不可达 —— 基线
> 3. e* 在 **CREATE** 算子类内可达 —— 方法
> 4. CREATE 的选择在**其证据通道**下把修复候选排在未修复候选之上 —— 通道
>
> 四项中三项**不是**环境属性。

**其后果**：**改进证据通道本身即可创造 C**（例如把每回合失败原因遥测——入坞速度、冲击次数、越界标志、悬停时长——接入 CREATE 的诊断步骤）。这是合法的方法贡献。

**这同时修正了我 P1 的让步**：我原文说"任何只看奖励文件的诊断对两边都可用，故不产生 C"——那句话与 ARG-10 立场**自相矛盾**。正确表述是：**通道不对称可以产生 C**，前提是该通道只挂载在 CREATE 一侧。

### 修正 7（部分收回）：ARG-5 的"不可消除"

"效度威胁不可消除"说过头了。**留出环境（hold-out environments）是合法且标准的做法。** 应保留的是"环境族 + 单调性"这一更强的报告策略，而非"不可消除"的断言。

审稿人称"预注册自我拆台"——**这一条我不接受**：从先导数据推导判据、再到新的环境族上验证，正是预注册的标准用法，不是循环论证。

### 修正 8（部分收回）：ARG-6 的检验

- **必要性检验的循环性批评公平**：可行性若由待检验的门控定义，则循环。应以**环境与 harness 层面**定义可行性来打破循环。
- **方差检验会误标最好的约束**：一个**必要但不充分**的约束会降低方差，因为它排除了破损实现。故方差检验**不能单独作为泄露判据**，需与 leave-one-check-out 结合。
- 审稿人称"terminal-on-success 被判成泄露"是**误读**，我表格中标的是接口。

### 审稿人给出的、我认为优于原回答的重新定位

> 负结果目前是**关于证据通道的陈述，不是关于环境的陈述**。而实测事实（可见性未诱导出该项、存在但权重错已 0/60）指向的瓶颈是**探索 / 信用分配与奖励尺度**，不是"缺失激励项"检测。核心问题应重写为：**为什么一行的解析释放条件（v0 ≈ 2d + 0.05）对 PPO 在 3M 步仍不可达？**

我验算了该解析式：阻尼 λ=2.0 时每步衰减因子 1/(1+dt·λ) = 1/(1+0.0333·2) = 0.9375，滑行距离 v0/λ = v0/2，与文件第 1 节实测的 `(v0−0.05)/2.0` 一致。**该任务存在可从观测计算的闭式最优策略，而 PPO 在 3M 步学不到**——这确实比"缺失激励项"更值得深挖。

### 我认为审稿人判错的地方（保留）

1. **C 是环境属性的可能性**：审稿人断言 C 必为联合属性。但若 EUREKA 的反思通道**结构上无法**挂载逐分量统计（而非仅仅"当前没挂"），则 C 仍可视为环境属性。**这需作者打开 `run_eureka_population.py:175-230` 看字段列表才能定论**——审稿人未查证即下结论。
2. **ARG-7 的一个残余价值**：审稿人称"可见 ≠ 会写"即杀死该机制。但损伤是**成功条件语义的一部分**（超阈值即失败），而 closing speed 只是达成手段。语义不同，可见性的诱导强度可能不同——故仍值得用 factorial 测，而非直接废弃。

### 修正 9（自我纠错）：我回答中的一个事实错误

我在论证"存在闭式释放解"时给出验算："阻尼 λ=2.0 时每步衰减因子 1/(1+dt·λ) = 1/(1+0.0333·2) = 0.9375"。

**这个中间步骤是错的。** 正确的推导：设离散每步衰减因子为 f，则滑行距离 = v0·dt·f/(1−f)。要使其等于文件第 1 节实测的 v0/2，需 f ≈ **0.9677**（即审稿人使用的连续式 e^(−λ·dt) = e^(−2/60) = 0.9672）。用 f=0.9375 代入会得到与实测不符的滑行距离。

结论（存在闭式最优策略 v0 ≈ 2d + v_f，且可从观测计算）**仍然成立**，但我的验算过程错误，且我把一个未通过的验算当作通过报出。记录于此。

### 修正 10（新增，来自完整审稿意见）：`0/60` 的上限只有 5%

60 个种子、0 次成功 → 由 rule of three，95% 置信上界约为 3/60 ≈ **5%**。

**后果**：研究中的任何候选**都从未与"≤5% 成功率"区分开来**。因此"0/60"不是精确的零，而是"不超过 5%"。这影响的不只是显著性，而是**结论方向**——所有以 0/60 为一端的对比，都无法区分 0% 与 4%。

**这也重新解释了我 P4 建议的"逐项相关性分析"**：审稿人指出，要求一个**常量预测子**（在某项上全部通过的候选）与**零方差结果**（三个都 0/60）相关，该统计量**在数学上未定义**。我的建议在 v4 那 16 个候选上不可执行。必须先用**有方差的候选集**（含未通过项者）或**更大样本**才能做。

### 修正 12（新增）：ARG-4 的内部张力是论文的真正核心难题

审稿人指出 ARG-4 要求编辑**同时**满足两个条件，而实测数据暗示它们**不相容**：
