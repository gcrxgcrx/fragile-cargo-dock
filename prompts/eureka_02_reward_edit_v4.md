# 必须避免的激励冲突（违反即无效）

任何辅助组件（低速、稳定、对齐、平滑等）都**不允许因为"推进任务所必需的动作"而下降**。

典型反例：用 `k / (1 + c * speed)` 形式的"低速因子"作为**持续的全局状态奖励**。推动目标物体必然产生速度，于是该组件在惩罚任务进展本身；一旦它的量级压过主信号，最优策略就变成"什么都不做"。

要求：
- "低速 / 静止 / 对齐"这类量只能作为**门控**，**不得作为全局持续奖励**被动收分；
- 任何组件都不得对"把目标推向目标位置"这一行为产生净负贡献。

**必做自检 ①**：把奖励分别代入 ①什么都不做、目标静止在初始位置；②正在把目标推向目标位置（目标因此具有速度）。要求 **②的单步总奖励严格高于 ①**。

# 必须让"完成事件"主导过程信号（违反即无效）

任务成功是一个**一次性事件**：目标物进入容差区、速度降到阈值以下、并连续保持若干步，且**一旦满足，episode 立即结束**。
如果奖励里只有过程型信号而没有完成事件的大额奖励，"一直在路上推""停在附近磨"就会成为局部最优。

要求：
- 完成条件必须从 `obs` 显式推断，容差**只能**取自环境事实里给出的几何与阈值；
- 量级：`10 * B > 3 * (所有过程型组件的单步奖励上限之和 * 400)`，其中 `B` 是满足完成条件时的奖励；
- 过程型组件应是**增量**形式（只在"这一帧更接近了"时给分），不是纯接近度。

**必做自检 ②**：③"停在目标外 0.3 m 处、速度接近 0、保持 400 步"；④"真正进入容差区并停稳"。
要求 **④整条轨迹的累计回报严格高于 ③**。

# 必须包含"接触轻柔度"信号，且量级不能太弱（违反即无效）

任务要求目标物被**轻柔**搬运：撞击过重会损坏目标并直接判失败。这是本环境成败的**核心技能**——
因为小车没有刹车，它必须"接近目标时提前松手，让地面阻力把目标带进去"，而不是一直推到最后一刻。

观测里**没有冲量/撞击力**这一维，必须自己构造可观测代理：

```python
crate_vx = next_obs[8] * 3.0
crate_vy = next_obs[9] * 3.0
crate_along_heading = crate_vx * obs[2] + crate_vy * obs[3]
closing = obs[4] * 3.0 - crate_along_heading
if closing < 0.0:
    closing = 0.0
contact = 1.0 if next_obs[14] > 0.5 else 0.0
gentleness = -0.05 * contact * closing
```

**量级要求（这一条最容易做错）**：实测有候选通过了"存在轻柔度项"的检查，却仍以 **1.55 m/s** 撞进目标区
（阈值 0.05 m/s），因为该项太弱、被推进奖励压过去了。所以：

- 当 `closing` 达到 1.0 m/s 量级时，该项的**惩罚必须与推进奖励同量级或更大**，使"高速撞击"在总奖励里明确不划算；
- 若你保留了"靠近目标就给分"的塑形项，就必须相应加大 `k`，直到满足下面的自检③；
- 该项**不得**在"接触但未接近"（`closing ≈ 0`）时产生惩罚——正常匀速推箱不能被判为撞击。

**必做自检 ③**：⑤"接触中、接近速度 1.0 m/s"；⑥"接触中、接近速度 0.05 m/s"。
要求 **⑤的单步总奖励明显低于 ⑥**（差距要与推进项同量级，不能只是 0.05 的零头）。

# 完成奖励必须是一次性事件，且完成状态下其余组件必须恰好为 0（违反即无效）

环境在"连续保持若干步满足完成条件"时会**立即终止 episode**。由此：

- 如果在成功**状态**上每步给分，策略的最优解是**永远不要走完最后一步**——那样收益流可以一直续着；
- 正确写法是**一次性事件**：整个 episode 只发一次。

**允许并推荐使用模块级状态。** 签名里没有 `done`，但 `obs[18]`（已用时间比例）在一个 episode 内
**单调递增**、重置时**回落**：

```python
_PREV_T = [-1.0]
_STREAK = [0]
_PAID = [False]

t = float(next_obs[18])
if t < _PREV_T[0] or t <= 1.0 / 400.0:
    _STREAK[0] = 0
    _PAID[0] = False
_PREV_T[0] = t
```

**同时，完成状态下除一次性事件外，其他组件的单步贡献之和必须恰好为 0。**
单步 0.3 看似无害，但 400 步累积是 120，而一次性事件可能被单步裁剪压到 20——**120 > 20，持久项照样赢**。
所以"对齐奖励/稳定奖励/低速奖励/接近度奖励"这类量**不得单独作为正项按步累积**，只能作为
**门控乘在增量信号上**，或只作为**惩罚**。

**必做自检 ④**：把 reward 在**同一个"停稳"状态**上连续调用 12 次。
要求：**除发一次性事件的那一次外，其余 11 次的返回值必须恰好为 0**（|值| < 1e-6）。

# 必须包含越界守卫（违反即无效）

目标物或小车离开场地会**直接判失败并结束 episode**。而生成奖励**拿不到任何"失败"信号**，
所以你必须自己从 `obs` 判断边界并在接近时惩罚。实测有候选完全没有边界项，结果 **40/40 回合直接冲出场外**。

- 小车位置在 `obs[0]`（x / 仓库半宽）与 `obs[1]`（y / 仓库半高）中。**`+1.0` 就是墙**，
  超过约 `1.05` 即出界；观测被裁剪到 ±2.0 **不是**物理范围。
- 必须给出一个**随越界接近而单调下降**的惩罚，且在 `|obs[0]|` 或 `|obs[1]|` 超过约 0.95 时就应明显生效。
- 若你的奖励里所有组件都 ≥ 0，且没有任何失败惩罚，那么"提前结束 episode"会变得有吸引力——
  这正是上面那个 40/40 出界候选的成因。

**必做自检 ⑤**：构造"小车位于场地中央"与"小车位于 `|obs[0]| = 1.05`（出界边缘）"两个状态，
要求后者的单步总奖励**明显更低**。
